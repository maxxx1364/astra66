# astra66 TBAE — موتور تحلیل بازار، سیگنال، ریسک و بک‌تست

**Trading Backtest & Analytics Engine**

پلتفرم مستقلِ تحلیل دادهٔ بازار با موتور محاسباتی سفارشی: تبدیل دادهٔ خام
یک‌دقیقه‌ای به هر تایم‌فریم، محاسبهٔ میله‌های سیستمی (تحرک خنثی‌نشده)، مرجع پویای
۱۰۰٪، دسته‌بندی و رنگ‌بندی میله‌ها، نقشهٔ حرارتی زمان‌های بازار — و روی همان پایه،
**لایهٔ استراتژی**: فیلترهای تأیید ورود، مدیریت ریسک با خروج پلکانی و stop پویا،
و بک‌تستی که هویت حسابداری‌اش با تست قفل شده است.

> نسخهٔ فعلی: `0.2.0` — فاز ۱ (موتور + API) **و فاز ۳ (بک‌تست استراتژی)**.
> زبان: Python خالص (کتابخانهٔ استاندارد؛ بدون numpy/pandas) — `562` تست.

**وضعیت پژوهشی در یک خط:** فیلترهای تأیید لبهٔ ناخالصِ مثبت و معنادار می‌سازند
(`+0.112R` در هر معامله، `t = +2.69`، n=372 روی ۲۰ پنجرهٔ مستقل)، اما پس از هزینه
در حد **سربه‌سر** است (`+0.004R`، بازهٔ اطمینان ۹۵٪ `[−0.067, +0.082]`) و
کم‌نمونه — یعنی **اعتبارسنجی‌نشده**. جزئیات و جدول کامل:
[`tbae/docs/RESEARCH.md`](tbae/docs/RESEARCH.md).

## ۱. اجرای سریع

```bash
cd tbae
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# تست‌ها (۵۶۲ تست، ≈ ۳۳ ثانیه)
python3 -m pytest

# API + Swagger
python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000     # سپس /docs

# خط فرمان
python3 -m app.cli                    --tf 15 --days 45 --out bars.csv   # میله‌های annotated
python3 -m app.cli backtest           --tf 15 --days 45                  # بک‌تست کامل
python3 -m app.cli compare            --tf 15 --days 45                  # استراتژی در برابر دو کنترل
python3 -m app.cli sweep              --tf 15 --days 45 --param min_edge_score --grid 0.3,0.45,0.6,0.8
python3 -m app.cli ablation           --tf 15 --days 45                  # سهم هر فیلتر

# پژوهش هزینه (۲۰ پنجرهٔ مستقل، ≈ ۲ دقیقه)
python3 scripts/cost_attribution.py --seeds 20 --days 45 --tf 15 --json reports/cost_attribution.json
```

هر سه منبع داده پشتیبانی می‌شوند:
`--feed synthetic:days=45,seed=7` (پیش‌فرض؛ قطعی و بدون نیاز به شبکه)،
`--feed csv:/path/to/minutes.csv`، و `--feed binance:BTCUSDT:days=45`
(نیاز به دسترسی شبکه؛ کد REST با pagination/retry و WebSocket با ring buffer نوشته
و آفلاین تست شده است).

## ۳. تعریف‌های ریاضی (هستهٔ موتور)

برای میله‌های منبع یک‌دقیقه‌ای `i = 1..n` در هر میلهٔ تایم‌فریم:

| کمیت | فرمول | توضیح |
|---|---|---|
| میلهٔ چارت (بدنه) | `chart_abs = \|close_n − open_1\|` | جابه‌جایی خالص |
| میلهٔ چارت (دامنه) | `chart_range = high − low` | کل دامنهٔ کندل |
| میلهٔ سیستمی | `S = Σ \|legs\|` | تحرک **خنثی‌نشده** |
| تفکیک جهت | `S_up = Σ legs⁺`، `S_down = Σ legs⁻` | سهم خرید/فروش |
| تحرک درون‌دقیقه‌ای | `S_intra = Σ (high_i − low_i)` | همیشه `≥ range` |
| بازدهی | `efficiency = chart_abs / S ∈ [0,1]` | سهم حرکت مفید از کل تحرک |

**مرجع پویای ۱۰۰٪:**
۱. مرتب‌سازی مقادیر، ۲. حذف `reference_max_outlier_share` (پیش‌فرض ۲٪) از
بالاترین‌ها به‌عنوان Max Bar، ۳. صدک `reference_percentile` (پیش‌فرض ۹۸) از
باقی‌مانده = ۱۰۰٪. سپس `chart_pct = chart_abs / chart_ref` و
`system_pct = S / system_ref`.

حالت پیش‌فرض `expanding` است (فقط تاریخِ تا همان لحظه) — چون `full` کل نمونه را
می‌بیند و در بک‌تست **look-ahead** است.

**درخت تصمیم دسته‌بندی (اولین تطابق برنده، پوشش کامل):**

| # | دسته | شرط | رنگ |
|---|---|---|---|
| ۱ | ضعیف | `chart_pct < 20%` و `system_pct < 20%` | خاکستری `#8a94a6` |
| ۲ | پرفشار | `system_pct ≥ 80%` و `chart_pct < 20%` | بنفش `#a855f7` |
| ۳ | پرانرژی | `chart_pct ≥ 55%` و `system_pct ≥ 55%` | سرمه‌ای `#1e3a8a` |
| ۴ | قوی | `chart_pct ≥ 55%` و `system_pct < 55%` | آبی `#3b82f6` |
| ۵ | متوسط | سایر موارد | سبز `#22c55e` (صعودی) / نارنجی `#f97316` (نزولی) |

> توجه فنی: چون `S ≥ chart_abs` همیشه برقرار است، «میلهٔ قوی» به‌صورت
> *حرکت مفید بزرگ با میلهٔ سیستمی متوسط* پیاده‌سازی شده (حرکت روان با کمترین
> درگیری) — دقیقاً همان مفهوم پروپوزال، اما به‌شکل ریاضیِ سازگار.

**امتیاز خانهٔ حرارتی (هر خانهٔ روز×ساعت):**

```
raw   = 0.50 × میانگین system_pct
      + 0.35 × میانگین chart_pct
      + 0.15 × میانگین efficiency
score = رتبهٔ صدکی raw  ∈ [0,1]
```

برش‌ها صدکی و پویا هستند: `timing_dead_share` (پیش‌فرض ۳۳٪ پایین) → زرد `#eab308`،
`timing_hot_share` (پیش‌فرض ۲۵٪ بالا) → قرمز `#dc2626`، میانه → قهوه‌ای `#8b5a2b`.

## ۴. لایهٔ استراتژی (سه پرسشی که این نسخه پاسخ می‌دهد)

### ۴.۱ چرا خروجی سیگنال محدود بود، و فیلترهای تأیید چه کردند

قیف ورود مرحله‌به‌مرحله گزارش می‌شود (نه یک عددِ «چند سیگنال»):

```
4407 میلهٔ آماده → 623 کاندیدای دسته‌بندی → 139 سیگنال پذیرفته‌شده (tf=15، ۴۵ روز)
```

فیلترها دو نوع‌اند: **hard** (رد قطعی: ADX پایین، RSI خارج بازه، گسترش بیش از حد،
شکست ساختار مخالف) و **soft** (پرچم: شواهد ضعیف‌تر، در امتیاز اثر می‌گذارند).
دلیل این تفکیک ساده است: زنجیرهٔ فیلترهای hard حجم سیگنال را نابود می‌کند.
یک پیچ تنظیم وجود دارد — `min_edge_score` — و `diagnose()` گلوگاه را نام می‌برد
(`narrowest_stage`, `most_decisive_filter`, `redundant_filters`).

**نتیجهٔ اندازه‌گیری‌شده:** با سخت‌گیری بیشتر، لبهٔ ناخالص قوی‌تر می‌شود —
`+0.046R (t=1.94)` در آستانهٔ ۰.۴۵ → `+0.124R (t=2.64)` در ۰.۸۰. پس «خروجی محدود»
بهای کیفیت است و آن کیفیت اندازه‌گیری‌شدنی است.

### ۴.۲ ریسک و خروج پلکانی با stop پویا

* **stop پویا از نوسان لحظه‌ای:** `sigma_structure_max` — بیشینهٔ σ و فاصلهٔ تا
  pivot تأییدشدهٔ ساختاری، سپس clamp به `[1.2σ, 3.2σ]` و بازهٔ درصدی.
  (بدون clamp، stop ساختاری در تایم‌فریم پایین منفجر می‌شود.)
* **خروج پلکانی:** trancheها در `entry + k·r·stop_distance`؛ بخشی از پوزیشن در
  سود بسته می‌شود، بقیه با stop منتقل‌شده به سربه‌سر و سپس trailing دنبال می‌کند؛
  یک runner با هدف سخت.
* **رویدادهای بازگشتی:** `leg_flow_flip`، `effort_vs_result`،
  `efficiency_collapse`، `engulfing`، `wick_rejection` — با شدتِ ترکیبی
  (`combine_severity`) به tighten / close_partial / close_all نگاشت می‌شوند.
  میلهٔ `weak` شاهدِ بازگشت **نیست** (فقط `pressure`)، و هر رویداد با RVِ خودِ میله
  نرمال و به بلوغ معامله شرط می‌شود.
* **درون‌میله‌ای:** فقط flow-flip در `elapsed == floor(tf × event_check_elapsed)`
  ارزیابی می‌شود — بقیهٔ رویدادها به میلهٔ کامل نیاز دارند و حدس زدنشان یعنی
  look-ahead.
* **مدیریت ریسک:** `qty × stop_distance == risk_cash` دقیقاً؛ دروازه‌های
  تعداد/بودجه/ضرر روزانه/drawdown/ضررهای پیاپی + cooldown؛ قرارداد «۰ = غیرفعال»
  برای limits درصدی.

### ۴.۳ دقت بک‌تست

* **تصمیم در میلهٔ `i−1`، اقدام در `i`** — fill روی همان میلهٔ تصمیم = look-ahead.
* **خروج دقیقه‌به‌دقیقه** با مسیر دقیقه‌ایِ واقعیِ میله (`minute_path`)؛
  `Fill.minute_index` اندیس صفر-بنیاد است و `ts` آن دقیقاً برابر
  `minute_path[minute_index].ts`.
* **ابهام درون‌میله‌ای بدبینانه حل می‌شود** (`adverse_first`): اگر در یک دقیقه هم
  استاپ و هم هدف لمس شود، استاپ زده می‌شود. حالت خوش‌بینانه برای تحلیل حساسیت
  موجود است و در manifest پرچم می‌خورد.
* **maker/taker:** ورود limit و هدف‌های TP سفارش ساکن‌اند ⇒ fill در قیمت هدف، بدون
  slip، با نرخ maker. استاپ/رویداد/زمان ⇒ taker + slippage + impact جذری.
* **ورود limit (pullback) به‌جای ورود با قیمت بازار:** ورود بازار روی میلهٔ
  پرجابه‌جاهی یعنی انتخاب نامساعد. سفارش limit داخل میلهٔ سیگنال کاشته می‌شود؛
  اگر قیمت فرار کند سفارش **باطل** می‌شود و دلیلش ثبت می‌گردد.
* **هویت حسابداری:** `net == gross − costs` روی تک‌تک معامله‌ها و
  `mean(net R) == mean(gross R) − mean(friction R)` بدون باقی‌مانده. هر نقض در
  `accounting_errors` ثبت و با تست رد می‌شود.
* **گارد look-ahead:** `reference_mode=full` در بک‌تست `ValueError` می‌دهد؛ با
  `allow_lookahead=True` اجرا می‌شود ولی در manifest ثبت و در warnings اعلام می‌گردد.
* **کنترل‌ها:** هر اجرا قابل مقایسه با ورود تصادفی و ورود هر-میله است — بدون
  کنترل، «استراتژی ضرر کرد» از «بازار نزولی بود» قابل تفکیک نیست.

## ۵. یافتهٔ پژوهشی (خلاصه)

`python3 scripts/cost_attribution.py --seeds 20 --days 45 --tf 15` روی ۲۴۰ اجرای
مستقل، با گردآوری در سطحِ معامله و bootstrap ایستا:

| آستانه | هندسهٔ خروج | n | grossR | t | fricR | netR | PF |
|---:|---|---:|---:|---:|---:|---:|---:|
| 0.45 | 3tranche / 2.2σ | 1380 | +0.046 | +1.94 | 0.187 | −0.141 | 0.74 |
| 0.75 | 3tranche / 4.4σ | 585 | +0.083 | +2.54 | 0.113 | −0.031 | 0.93 |
| 0.80 | 3tranche / 2.2σ | 377 | +0.124 | +2.64 | 0.166 | −0.042 | 0.92 |
| **0.80** | **3tranche / 4.4σ** | **372** | **+0.112** | **+2.69** | **0.108** | **+0.004** | **1.02** |

و کنترل‌ها (`python3 -m app.cli compare --tf 15 --days 45 --seed 7`):

| پیکربندی | معاملات | بازده٪ | Sharpe | maxDD٪ | E[R] | PF |
|---|---:|---:|---:|---:|---:|---:|
| **استراتژی** | 57 | −2.09 | −1.85 | 3.20 | **−0.115** | 0.81 |
| کنترل ورود تصادفی | 104 | −6.62 | −6.62 | 6.97 | −0.348 | 0.59 |
| کنترل ورود هر-میله | 184 | −18.09 | −13.58 | 18.16 | −0.465 | 0.40 |
| خرید و نگهداری | — | −26.22 | — | 37.86 | — | — |

**سه نتیجهٔ قابل دفاع:**
۱. فیلترهای تأیید سیگنالِ با کیفیت می‌سازند (لبهٔ ناخالص مثبت و معنادار در همهٔ
آستانه‌ها، و ۳ برابر بهتر از کنترل تصادفی).
۲. استراتژی با استاپ تنگ **cost-bound** است، نه signal-bound — پس درمانش هندسی است
(استاپ گسترده‌تر، پای taker کمتر، اهداف maker) نه فیلتر بیشتر.
۳. وضعیت خالص فعلی **سربه‌سرِ اعتبارسنجی‌نشده** است: `n=372` در برابر حداقل ۵۶۹
معاملهٔ لازم برای توان ۸۰٪، و بازهٔ اطمینان شامل صفر.

**قدم بعدی:** هزینهٔ واقعی صرافی به‌جای فرض، و دادهٔ تاریخی واقعیِ چندساله تا `n`
از آستانهٔ توان بگذرد. جدول کامل، اهرم‌های بهبود و ۲۴ باگ واقعیِ اصلاح‌شده در
[`tbae/docs/RESEARCH.md`](tbae/docs/RESEARCH.md).

| `GET /api/monte-carlo` | توزیع drawdown و بازده با block-resampling + bootstrap |
| `GET/POST/DELETE /api/rules` | قوانین رنگ دلخواه کاربر |
| `GET/POST/DELETE /api/keymap` | نگاشت کلید → فرمان |
| `POST /api/reset` | بازگشت قوانین و کلیدها به پیش‌فرض |
| `POST /api/upload` | بارگذاری CSV شخصی (اعتبارسنجی پیش از ذخیره) |

پارامترهای نامعتبر `422` با پیامِ راهنما برمی‌گردانند؛ `reference_mode=rolling`
بدون `reference_window` و `reference_mode=full` بدون `allow_lookahead` رد می‌شوند.

## ۷. کلیدهای پیش‌فرض

۲۳ binding برای ۲۴ فرمان (کلیدها از داخل داشبورد قابل تغییرند و در
`data/user_rules.json` ذخیره می‌شوند؛ آن فایل در `.gitignore` است چون وضعیت کاربر
است نه پیکربندی پروژه).

| کلید | فرمان | | کلید | فرمان |
|---|---|---|---|---|
| `Space` | پخش/توقف بازپخش | | `1..5` | فیلتر دسته‌های پنج‌گانه |
| `+` / `−` | سرعت بازپخش | | `H` | فقط ساعات پرانرژی |
| `→` | یک گام به جلو | | `0` | پاک کردن فیلترها |
| `R` | بازنشانی بازپخش | | `N` / `P` | پرش به میلهٔ قوی/پرفشار بعدی |
| `[` / `]` | تایم‌فریم کوچک‌تر/بزرگ‌تر | | `E` | خروجی CSV |
| `S` / `V` | میلهٔ سیستمی / حجم | | `D` / `L` | حالت تاریک / زبان |

`F5`, `F11`, `F12`, `Tab`, `Escape` و کلیدهای فقط-فاصله رد می‌شوند (رزرو مرورگر /
binding نامرئی). زبان قواعد کاربر مقایسه و `and/or/not` و پرانتز است — **بدون
`eval`**؛ حساب (arithmetic) عمداً پشتیبانی نمی‌شود و با پیامِ راهنما رد می‌شود.

## ۸. وضعیت راستی‌آزمایی
