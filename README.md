# astra66 TBAE — موتور بک‌تست و تحلیل معاملات
Trading Backtest & Analytics Engine
پلتفرم مستقل تحلیل داده بازار با موتور محاسباتی سفارشی: تبدیل داده خام یک‌دقیقه‌ای به هر تایم‌فریم،
محاسبهٔ میله‌های سیستمی (تحرک خنثی‌نشده)، مرجع پویای ۱۰۰٪، دسته‌بندی و رنگ‌بندی میله‌ها،
نقشهٔ حرارتی زمان‌های بازار، بازپخش دادهٔ تاریخی با سرعت قابل تنظیم، و دفترچه کلیدهای پویا.
> نسخهٔ فعلی: `0.1.0` — فاز ۱ پروپوزال (موتور + داشبورد + لایهٔ سفارشی‌سازی).
---
۱. اجرای سریع
```bash
cd tbae
python3 -m pip install -r requirements.txt

# داشبورد (پیش‌فرض: http://0.0.0.0:8000)
python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# یا بدون UI — خروجی متنی/CSV از موتور
python3 -m app.cli --tf 15 --days 45 --out bars.csv
```
تست‌ها:
```bash
python3 -m pytest            # ۴۷ تست واحد برای موتور، قوانین و API
node tests/smoke\_dashboard.cjs http://127.0.0.1:8000   # تست سطح مرورگر داشبورد
```

۳. تعریف‌های ریاضی (هستهٔ موتور)
برای هر پنجرهٔ زمانی با میله‌های منبع یک‌دقیقه‌ای `i = 1..n`:
کمیت	فرمول	توضیح
میله چارت (بدنه)	`chart_abs =	close_n − open_1
میله چارت (دامنه)	`chart\_range = high − low`	کل دامنه کندل
میله سیستمی	`S =	c_1 − o_1
تفکیک جهت	`S\_up = Σ legs⁺` ، `S_down = Σ	legs⁻
تحرک درون‌دقیقه‌ای	`S\_intra = Σ (high\_i − low\_i)`	سایه‌های داخلی
بازدهی	`efficiency = chart\_abs / S` (محدود به ۰..۱)	سهم حرکت مفید از کل تحرک
مرجع پویای ۱۰۰٪
۱. مرتب‌سازی مقادیر، ۲. حذف `reference\_max\_outlier\_share` (پیش‌فرض ۲٪) از بالاترین‌ها به‌عنوان
Max Bar، ۳. صدک `reference\_percentile` (پیش‌فرض ۹۸) از باقی‌مانده = ۱۰۰٪.
سپس `chart\_pct = chart\_abs / chart\_ref` و `system\_pct = S / system\_ref`.
درخت تصمیم دسته‌بندی (اولین تطابق برنده، پوشش کامل)
#	دسته	شرط	رنگ
۱	ضعیف	`chart\_pct < 20%` و `system\_pct < 20%`	خاکستری `#8a94a6`
۲	پرفشار	`system\_pct ≥ 80%` و `chart\_pct < 20%`	بنفش `#a855f7`
۳	پرانرژی	`chart\_pct ≥ 55%` و `system\_pct ≥ 55%`	سرمه‌ای `#1e3a8a`
۴	قوی	`chart\_pct ≥ 55%` و `system\_pct < 55%`	آبی `#3b82f6`
۵	متوسط	سایر موارد	سبز `#22c55e` (صعودی) / نارنجی `#f97316` (نزولی)
> توجه فنی: از آنجا که `S ≥ chart\_abs` همیشه برقرار است، «میله قوی» به‌صورت
> \*حرکت مفید بزرگ با میله سیستمی متوسط\* پیاده‌سازی شده است (حرکت روان با کمترین درگیری) —
> دقیقاً همان مفهوم پروپوزال، اما به شکل matematically سازگار.
امتیاز نقشه حرارتی (هر خانهٔ روز×ساعت)
```
score = 0.50 × میانگین system\_pct
      + 0.35 × میانگین chart\_pct
      + 0.15 × میانگین efficiency
```
برش‌ها صدکی و پویا هستند: `timing\_dead\_share` (پیش‌فرض ۳۳٪ پایین) → زرد `#eab308`،
`timing\_hot\_share` (پیش‌فرض ۲۵٪ بالا) → قرمز `#dc2626`، میانه → قهوه‌ای `#8b5a2b`.

۴. API
Endpoint	توضیح
`GET /api/meta`	مجموعه‌داده‌ها، تایم‌فریم‌ها، دسته‌ها، رنگ‌ها، رجیستری فرمان‌ها
`GET /api/data?tf=\&limit=\&weak\_threshold=\&big\_threshold=\&pressure\_system\_threshold=\&reference\_percentile=\&hot\_only=`	میله‌های annotated + خلاصه KPI + خانه‌های حرارتی
`GET /api/raw?minutes=\&end=`	داده خام ۱ دقیقه‌ای برای بازپخش
`GET /api/path?tf=\&ts=`	منحنی رشد یک میله + میانگین همان بازهٔ (روز، ساعت)
`GET /api/table?tf=\&category=\&from\_ts=\&to\_ts=`	دادهٔ جدول با فیلتر
`GET/POST/DELETE /api/rules`	قوانین رنگ دلخواه کاربر
`GET/POST/DELETE /api/keymap`	نگاشت کلید → فرمان
`GET /api/commands`	رجیستری فرمان‌ها (۲۱ فرمان در ۶ گروه)
`POST /api/upload`	بارگذاری CSV شخصی
`POST /api/reset`	بازگشت قوانین و کلیدها به پیش‌فرض
`GET /docs` (Swagger) به‌صورت خودکار در دسترس است.

۵. کلیدهای پیش‌فرض
کلید	فرمان		کلید	فرمان
`Space`	پخش/توقف بازپخش		`1..5`	فیلتر دسته‌های پنج‌گانه
`+` / `−`	سرعت بازپخش		`H`	فقط ساعات پرانرژی
`→`	یک گام به جلو		`0`	پاک کردن فیلترها
`R`	بازنشانی بازپخش		`N` / `P`	پرش به میله قوی/پرفشار بعدی
`\[` / `]`	تایم‌فریم کوچک‌تر/بزرگ‌تر		`E`	خروجی CSV
`S` / `V`	میله سیستمی / حجم		`D` / `L`	حالت تاریک / زبان
هر کلید از داخل داشبورد قابل تغییر است و در `data/user\_rules.json` ذخیره می‌شود.
